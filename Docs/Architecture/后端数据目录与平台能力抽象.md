# 后端数据目录与平台能力抽象

## 定位

本文用于支撑新 UI 独立开发，但不预设新 UI 的页面形态、布局方式或交互模式。

目标不是为某个页面补接口，而是把现有后端能力抽成 UI 无关的平台层，让任意新交互都能稳定完成三件事：

- 找到数据在哪里。
- 知道当前对象能做什么。
- 追踪动作产生了哪些运行、产物和调试信息。

本文只定义后端数据目录、资源抽象和落地任务边界；具体 UI 信息架构、页面流和视觉设计另行决定。

## 现状判断

当前后端已经有一部分平台能力雏形，但入口分散：

- `Apps/Api/lib/modules/catalog.js` 是能力目录，描述可启动模块。
- `Infrastructure/ArtifactIndex/artifact-index.js` 是样例库、artifact tree 和 cache 索引。
- `Apps/Api/lib/stores/workflow-run-store.js` 是 workflow run 索引和持久化入口。
- `Apps/Api/lib/stores/job-store.js` 是后台 job 索引和归档入口。
- `Apps/Api/lib/stores/artifact-reader.js` 负责读取当前样例 artifact。
- `Apps/Api/lib/active-turns/store.js` 维护 active agent turn 绑定。
- `Apps/Api/lib/agent-chat/conversation-store.js` 维护 Agent conversation、确认方案和 revision。
- `Infrastructure/Storage/local-store.js` 负责 Runtime 根目录、样例目录和 runtime URI 边界。
- `Infrastructure/Observability/stage-logger.js` 负责 stage log 和 DebugSnapshot。
- `Apps/Api/server.js` 直接组合了大量旧路由、兼容路由、workflow 路由和 function-slot 路由。

问题不是缺少数据，而是缺少一层明确的资源目录和解析协议。新 UI 如果直接复用旧路由，会被迫理解这些内部存储差异，交互一变就容易继续堆分支。

## 基本原则

### 1. 先抽平台能力，不抽页面数据

后端优先提供资源、动作、运行状态、血缘和调试能力，不优先提供 `dashboardData`、`samplePageData` 这类页面专用大对象。

页面级 projection 可以在具体 UI 稳定后再加，而且必须建立在平台能力之上。

### 2. 区分事实源、索引和投影

- 事实源：核心数据真实存放位置，例如 Runtime artifact、workflow run 文件、conversation 文件、FunctionSlotLibrary 文件。
- 索引：便于查找、列表、cache 命中的派生结构，例如 ArtifactIndex、WorkflowRun index、active jobs。
- 投影：为查询或下游消费整理出的派生视图，例如 FunctionSlotProjection、未来 ResourceProjection。

索引和投影可以重建，不应成为唯一真相来源。

### 3. 前端只拿安全引用，不读本地路径

前端使用后端返回的 `uri`、`artifactId`、`resourceId`、`traceId` 等安全引用。不得依赖本地绝对路径、Runtime 目录结构或文件名规则。

### 4. 动作由后端声明

新 UI 的交互可能是按钮、命令面板、图谱节点、右键菜单或快捷键。前端不应硬编码“某对象能做什么”。

后端应能基于资源状态返回可用动作、禁用原因、风险提示和执行命令。

### 5. 追踪字段是平台合同的一部分

所有核心资源、运行和动作结果都必须保留：

- `runId`
- `traceId`
- `stageId`
- `artifactId`
- `parentArtifactId`

缺失时显式为 `null`，不要省略。

## 资源类型目录

| resourceKind | 业务含义 | 当前事实源 | 当前索引/查询入口 | 备注 |
| --- | --- | --- | --- | --- |
| `sample` | 一个样例视频及其当前处理结果 | `Runtime/Artifacts/<sampleVideoId>/artifact.json` | `ArtifactIndex.listItems/getItem/loadItem`、`artifact-reader.loadCurrentSampleArtifact` | ArtifactIndex 是样例库和 cache 索引，不是完整事实源 |
| `artifact` | 任一阶段产物或媒体派生产物 | Runtime artifact JSON、sample artifact 内嵌 ref、FunctionSlotLibrary 文件 | 目前缺少统一 resolver | 需要新增 `ArtifactResolver` |
| `workflowRun` | 一次 workflow 执行 | `Runtime/WorkflowRuns/runs/*.json` | `workflow-run-store`、`workflow-routes` | 已有 per-run file 和 index |
| `job` | 后台处理任务 | `Runtime/Jobs/active-jobs.json`、`Runtime/Jobs/archive/*.jsonl` | `job-store` | terminal job 会归档 |
| `module` | 可执行能力定义 | `Apps/Api/lib/modules/catalog.js` | `moduleRegistry.list/getByModuleId` | 适合作为 command/action 的能力来源之一 |
| `trace` | 一次可观测链路 | `Runtime/DebugSnapshots/<traceId>.log.jsonl` | `observability/debug-traces` | DebugSnapshot 也在同目录 |
| `debugSnapshot` | 受控调试细节 | `Runtime/DebugSnapshots/<snapshotId>.json` | `stage-logger.writeDebugSnapshot`、debug trace detail | 普通 API 只暴露安全摘要和 URI |
| `activeTurn` | 正在运行或可恢复的 Agent turn 绑定 | `Runtime/ActiveTurns/active-turns.json` | `active-turns/store.js` | 绑定 owner、thread、turn、artifact、trace |
| `conversation` | Agent 会话、消息、确认方案 | `Runtime/AgentConversations/*.json` | `agent-chat/conversation-store.js` | 带 revision，适合 command 乐观并发 |
| `libraryItem` | FunctionSlotLibrary 入库样例 | `Artifacts/FunctionSlotLibrary/<artifactId>/*` | `function-slot-library/service.js` | 与 Runtime sample artifact 不同源 |
| `projection` | 派生检索视图 | `Runtime/Projection/*` | `function-slot-projection/service.js` | 当前主要服务功能槽位查询 |

## UI 无关平台层

建议新增 `Apps/Api/lib/platform/`，承载以下模块。

### ResourceCatalog

职责：

- 维护 `resourceKind` 到事实源、索引、resolver、action provider 的映射。
- 输出安全的资源目录，帮助前端和开发者知道系统有哪些资源能力。

输入：

```ts
type ResourceCatalogQuery = {
  includeInternal?: boolean;
};
```

输出：

```ts
type ResourceKindEntry = {
  resourceKind: string;
  label: string;
  idFields: string[];
  sourceOfTruth: string;
  indexSource: string | null;
  supportsList: boolean;
  supportsRead: boolean;
  supportsLineage: boolean;
  supportsActions: boolean;
  schemaVersion: string;
};
```

### ResourceResolver

职责：

- 按 `resourceKind + id` 读取资源摘要。
- 不暴露完整敏感内容。
- 不返回本地绝对路径。

输入：

```ts
type ResourceRef = {
  resourceKind: string;
  resourceId: string;
};
```

输出：

```ts
type ResourceSummary = {
  schemaVersion: "platform_resource_summary.v1";
  resourceKind: string;
  resourceId: string;
  label: string | null;
  status: string | null;
  createdAt: string | null;
  updatedAt: string | null;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  artifactId: string | null;
  parentArtifactId: string | null;
  summary: Record<string, unknown> | null;
  source: {
    sourceOfTruth: string;
    indexSource: string | null;
  };
};
```

### ArtifactResolver

职责：

- 通过 `artifactId` 定位 artifact 的类型、来源、父级、媒体 URI、摘要和可读状态。
- 屏蔽 Runtime、sample artifact、FunctionSlotLibrary、projection 等底层差异。

输入：

```ts
type ArtifactResolveRequest = {
  artifactId: string;
  sampleVideoId?: string | null;
};
```

输出：

```ts
type ArtifactResolution = {
  schemaVersion: "artifact_resolution.v1";
  artifactId: string;
  artifactType: string | null;
  stageName: string | null;
  parentArtifactId: string | null;
  sampleVideoId: string | null;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  uri: string | null;
  mediaKind: "video" | "audio" | "image" | "json" | "text" | "unknown";
  exists: boolean;
  readable: boolean;
  summary: Record<string, unknown> | null;
  source: {
    sourceOfTruth: string | null;
    indexSource: string | null;
  };
};
```

### LineageResolver

职责：

- 返回资源或 artifact 的父级、子级、相关 trace 和相关 run。
- 支持前端任意呈现为图谱、时间线、树或列表。

输出：

```ts
type ResourceLineage = {
  schemaVersion: "resource_lineage.v1";
  root: ResourceRef;
  nodes: Array<ResourceSummary>;
  edges: Array<{
    from: ResourceRef;
    to: ResourceRef;
    relation: "parent" | "child" | "produced_by" | "used_by" | "trace" | "version_of" | string;
  }>;
};
```

### RuntimeStateResolver

职责：

- 统一 workflow run、job、active turn 的运行状态表达。
- 对外提供通用状态，而不是让前端理解每套内部状态枚举。

输出：

```ts
type RuntimeState = {
  schemaVersion: "runtime_state.v1";
  resource: ResourceRef;
  status: "idle" | "queued" | "running" | "waiting" | "blocked" | "processed" | "partial_failed" | "failed" | "canceled" | string;
  progress: number | null;
  currentStages: Array<{
    key: string;
    stageName: string | null;
    status: string;
    runId: string | null;
    traceId: string | null;
    stageId: string | null;
    artifactId: string | null;
    parentArtifactId: string | null;
    errorSummary: Record<string, unknown> | null;
  }>;
  retryable: boolean | null;
  errorSummary: Record<string, unknown> | null;
};
```

### ActionRegistry

职责：

- 基于资源状态声明可用动作。
- 将 UI 交互统一转成后端 command。
- 支持禁用原因、确认要求、输入 schema 和影响范围说明。

输出：

```ts
type ResourceAction = {
  actionKey: string;
  label: string;
  enabled: boolean;
  disabledReason: string | null;
  requiresConfirm: boolean;
  dangerLevel: "none" | "low" | "medium" | "high";
  inputSchema: Record<string, unknown> | null;
  effects: {
    createsRun: boolean;
    createsArtifact: boolean;
    mayInvalidateDownstream: boolean;
    affectedResourceRefs: ResourceRef[];
  };
};
```

命令输入：

```ts
type PlatformCommand = {
  command: string;
  target: ResourceRef;
  options?: Record<string, unknown>;
  expectedRevision?: number | null;
};
```

命令输出：

```ts
type PlatformCommandResult = {
  schemaVersion: "platform_command_result.v1";
  ok: boolean;
  command: string;
  target: ResourceRef;
  status: string;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  artifactId: string | null;
  parentArtifactId: string | null;
  resourceRefs: ResourceRef[];
  errorSummary: Record<string, unknown> | null;
};
```

## 建议 HTTP 入口

这些入口是平台能力入口，不是页面接口。

```text
GET  /api/platform/v1/catalog
GET  /api/platform/v1/resources?kind=<resourceKind>
GET  /api/platform/v1/resources/:resourceKind/:resourceId
GET  /api/platform/v1/resources/:resourceKind/:resourceId/lineage
GET  /api/platform/v1/resources/:resourceKind/:resourceId/actions
GET  /api/platform/v1/artifacts/:artifactId
GET  /api/platform/v1/runtime-state/:resourceKind/:resourceId
GET  /api/platform/v1/traces/:traceId
POST /api/platform/v1/commands
```

当前稳定平台入口：

```text
GET /api/platform/v1/catalog
GET /api/platform/v1/catalog?includeInternal=true
GET /api/platform/v1/resources?kind=<resourceKind>
GET /api/platform/v1/resources/:resourceKind/:resourceId
GET /api/platform/v1/resources/:resourceKind/:resourceId/lineage
GET /api/platform/v1/artifacts/:artifactId
GET /api/platform/v1/artifacts/:artifactId?sampleVideoId=<sampleVideoId>
GET /api/platform/v1/runtime-state/:resourceKind/:resourceId
GET /api/platform/v1/traces/:traceId
GET /api/platform/v1/resources/:resourceKind/:resourceId/actions
POST /api/platform/v1/commands
```

其中 artifact 解析第一版优先从 `ArtifactIndex` 的 artifact tree 命中，找不到时回退到 sample artifact 内嵌引用；暂不承诺全局孤儿 artifact 和 FunctionSlotLibrary 深解析。

其中 resources 读取第一版覆盖 `sample`、`workflowRun`、`job`、`activeTurn`、`conversation`、`module`、`trace`，只返回安全摘要，不返回完整 artifact、完整 conversation messages、完整 trace events 或本地绝对路径。`artifact` 仍使用专用 artifact resolver。

其中 lineage 第一版覆盖 `sample` 和 `artifact`，基于 `ArtifactIndex` 的 artifact tree 生成节点和边。该结果是可重建索引投影，不是新的事实源；暂不推断 workflow、agent conversation 或跨库 FunctionSlotLibrary 的深层血缘。

其中 runtime state 解析第一版覆盖 `workflowRun`、`job`、`activeTurn`，保留 `rawStatus`，同时输出归一化 `status`。它不合并内部 store，也不改变 job 归档、workflow run 持久化或 active turn recovery 策略。

其中 trace 读取通过 `TraceResolver` 输出安全 `platform_trace_detail.v1`，只暴露阶段事件摘要、错误摘要、`logUri` 和 `debugSnapshotUri` 安全引用；不返回完整 prompt、完整素材内容、完整本地路径或未折叠的大对象。

其中 resource actions 覆盖 `workflow.stage.rerun`、`job.cache.resolve`、`agent.turn.stop`、`agent.turn.retry`、`conversation.archive`。action 是后端声明的能力合同，每个 action 必须返回 `enabled`、`disabledReason`、`dangerLevel`、`effects` 和输入 schema。`agent.turn.retry` 当前只在旧 active-turn replay 路由中安全承接，platform action 中保留声明但 `enabled=false`，`disabledReason=active_turn_retry_requires_legacy_replay_route`，避免 command 合同承诺尚未抽成稳定 service 的复杂 replay 能力。

其中 commands 稳定转译到已有业务 service/runtime，不重新实现业务流程：

- `workflow.stage.rerun` 转译到现有 workflow service 的 `rerunStage`。
- `job.cache.resolve` 转译到 `moduleRegistry.resolveModuleCacheDecision` 或 `shotBoundaryService.resolveCacheDecision`。
- `agent.turn.stop` 转译到 `activeTurnRuntime.cancel`。
- `conversation.archive` 转译到 `agentConversationStore.archive`。

暂不在 platform command 执行 `agent.turn.retry`，因为旧 retry 路由包含 replay 输入校验、thread/lease 管理、新旧 turn 关系和 owner 回写；后续若要纳入 command，必须先抽出可复用 retry service，不能在 platform 层复制路由流程。

约束：

- 返回对象必须带 `schemaVersion`。
- platform API 错误返回必须使用 `platform_error.v1`，并带安全 `message`、`code`、`resource`、`traceId`、`debugSnapshotUri`、`stageName`、`retryable`。读接口可在非异常 404 中返回 `traceId=null`、`debugSnapshotUri=null`；执行异常必须由 API 失败追踪生成 `DebugSnapshot` 后返回引用。
- 不返回本地绝对路径。
- 不返回完整 prompt、完整素材内容或未脱敏路径。
- 读接口不得触发重跑、生成、删除等副作用。

## 和旧接口的关系

短期内旧接口继续保留：

- 旧 Workbench 仍使用当前 `Apps/Workbench/src/api/client.ts`。
- 新 UI 可以直接使用 platform API。
- 新增 platform API 不替换旧业务 service，只在旧 service、store、index 之上做资源解析和安全投影。

允许复用：

- `moduleRegistry` 作为 command 能力来源。
- `artifactIndex` 作为 sample/list/cache 查询来源。
- `workflowRunStore` 和 `jobStore` 作为运行状态来源。
- `stage-logger` 和 `debug-traces` 作为追踪来源。
- `moduleRegistry`、`shotBoundaryService`、`activeTurnRuntime`、`agentConversationStore` 作为 command 转译目标。

不允许：

- 为新 UI 复制一套业务流程。
- 在 platform 层重新实现模型调用、媒体处理或分析逻辑。
- 让 platform 层静默覆盖旧 artifact 或 workflow run。

## 审查风险

- 如果先做页面级 BFF，会再次把后端绑定到某套 UI。
- 如果前端直接读 Runtime 结构，会形成不可替换的隐式合同。
- 如果把 ArtifactIndex 当事实源，索引损坏或重建时会丢语义。
- 如果动作可用性继续散落在 UI，交互一变化就会复制判断。

- 如果 resource contract 不带 schemaVersion，后续演进会伤到新旧 UI 并行开发。
