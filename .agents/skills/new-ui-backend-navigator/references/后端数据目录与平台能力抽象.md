# 后端数据目录与平台能力抽象

## 文档定位

本文是新 UI 接入后端能力时的稳定合同说明，不是阶段计划，也不是页面设计稿。

平台层的目标是把已有后端能力整理成 UI 无关的资源、状态、动作、产物、血缘和追踪接口。新 UI 可以用这些接口组合列表、图谱、时间线、详情页、命令面板或其他交互形态；后端不提前绑定任何具体页面。

本文回答三件事：

- 数据在哪里，哪些是事实源，哪些只是索引或投影。
- 前端通过什么资源合同读取数据、触发动作、追踪结果。
- 当前稳定能力边界是什么，哪些能力仍不能承诺。

## 核心原则

### 平台能力优先于页面数据

后端提供 `resource / artifact / runtime state / action / command / trace` 等能力，不提供 `dashboardData`、`samplePageData` 这类页面专用大对象。

如果未来某个新 UI 交互稳定后确实需要 projection，可以在平台能力之上加轻量投影，但不能绕过平台层直接绑定 Runtime 文件结构。

### 事实源、索引、投影分离

事实源保存业务真实数据，例如 Runtime artifact、workflow run 文件、Agent conversation 文件、FunctionSlotLibrary 文件。

索引用于查找和列表，例如 ArtifactIndex、WorkflowRun index、active jobs。索引可以重建，不是唯一真相来源。

投影用于下游消费或检索，例如 FunctionSlotProjection 或未来 ResourceProjection。投影同样不能成为唯一事实源。

平台读取链路应保持：

```text
事实源 -> resolver -> index/projection -> platform API
```

### 前端只使用安全引用

新 UI 使用 `resourceId`、`artifactId`、`traceId`、`uri` 等后端返回的安全引用，不读取本地绝对路径，不猜 Runtime 目录结构，不依赖文件名规则。

`uri` 只能是后端可服务的安全路径，例如 `/runtime/...`，或为 `null`。

### 动作由后端声明

前端不硬编码“这个对象现在能做什么”。资源当前可用动作由后端返回：

- 是否可执行：`enabled`
- 为什么不可执行：`disabledReason`
- 是否需要确认：`requiresConfirm`
- 风险等级：`dangerLevel`
- 影响范围：`effects`
- 执行所需输入：`inputSchema`

同一个 action 可以被 UI 表现成按钮、右键菜单、快捷键、图谱节点操作或命令面板项，后端合同不因此变化。

### 追踪字段是合同字段

平台返回的核心资源、运行状态、产物和命令结果必须显式保留这些字段：

```text
runId
traceId
stageId
artifactId
parentArtifactId
```

缺失时返回 `null`，不要省略字段。这样新 UI 能稳定把资源、运行、产物和调试信息串起来。

## 当前资源目录

| resourceKind | 含义 | 事实源 | 索引或查询入口 | 当前平台能力 |
| --- | --- | --- | --- | --- |
| `sample` | 一个样例视频及其当前处理结果 | `Runtime/Artifacts/<sampleVideoId>/artifact.json` | `Infrastructure/ArtifactIndex`、`artifact-reader` | list/read/lineage/actions |
| `artifact` | 阶段产物或媒体派生产物 | Runtime artifact JSON、sample artifact 内嵌 ref、FunctionSlotLibrary 文件 | `ArtifactResolver`、`ArtifactIndex artifactTree` | read/lineage/actions |
| `workflowRun` | 一次 workflow 执行 | `Runtime/WorkflowRuns/runs/*.json` | `workflow-run-store` | list/read/runtime-state/actions |
| `job` | 后台处理任务 | `Runtime/Jobs/active-jobs.json`、`Runtime/Jobs/archive/*.jsonl` | `job-store` | list/read/runtime-state/actions |
| `module` | 后端可执行能力定义 | `Apps/Api/lib/modules/catalog.js` | `moduleRegistry` | list/read/actions |
| `trace` | 一次可观测链路 | `Runtime/DebugSnapshots/<traceId>.log.jsonl` | `debug-traces`、`TraceResolver` | list/read |
| `debugSnapshot` | 受控调试细节 | `Runtime/DebugSnapshots/<snapshotId>.json` | `stage-logger.writeDebugSnapshot` | 仅通过安全 URI 引用 |
| `activeTurn` | 正在运行或可恢复的 Agent turn 绑定 | `Runtime/ActiveTurns/active-turns.json` | `active-turns/store.js` | list/read/runtime-state/actions |
| `conversation` | Agent 会话、消息、确认方案和 revision | `Runtime/AgentConversations/*.json` | `agent-chat/conversation-store.js` | list/read/actions |
| `libraryItem` | FunctionSlotLibrary 入库样例 | `Artifacts/FunctionSlotLibrary/<artifactId>/*` | `function-slot-library/service.js` | catalog/read 方向已登记，深层解析仍按库 service |
| `projection` | 派生检索视图 | `Runtime/Projection/*` | `function-slot-projection/service.js` | internal catalog entry |

## 平台模块

实现集中在：

```text
Apps/Api/lib/platform/
```

### ResourceCatalog

文件：`Apps/Api/lib/platform/resource-catalog.js`

职责：

- 暴露系统支持的资源类型。
- 标明每类资源的事实源、索引来源和能力 flags。
- 支持 `includeInternal=true` 查看内部投影类资源。

典型输出项：

```ts
type ResourceKindEntry = {
  schemaVersion: "platform_resource_catalog.v1";
  resourceKind: string;
  label: string;
  idFields: string[];
  sourceOfTruth: string;
  indexSource: string | null;
  supportsList: boolean;
  supportsRead: boolean;
  supportsLineage: boolean;
  supportsActions: boolean;
};
```

### ResourceResolver

文件：`Apps/Api/lib/platform/resource-resolver.js`

职责：

- 按 `resourceKind + resourceId` 返回资源安全摘要。
- 支持资源列表和单资源读取。
- 不返回完整 artifact、完整 conversation messages、完整 trace events 或本地绝对路径。

当前覆盖：

```text
sample
workflowRun
job
activeTurn
conversation
module
trace
```

`artifact` 走专用 `ArtifactResolver`。

核心输出：

```ts
type ResourceSummary = {
  schemaVersion: "platform_resource_summary.v1";
  resourceKind: string;
  resourceId: string;
  label: string | null;
  status: string | null;
  createdAt: string | null;
  updatedAt: string | null;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  artifactId: string | null;
  parentArtifactId: string | null;
  summary: Record<string, unknown> | null;
  source: {
    sourceOfTruth: string | null;
    indexSource: string | null;
  };
};
```

### ArtifactResolver

文件：`Apps/Api/lib/platform/artifact-resolver.js`

职责：

- 通过 `artifactId` 定位产物类型、阶段、父级、来源、URI、摘要和可读状态。
- 优先从 `ArtifactIndex` 的 artifact tree 命中。
- 找不到 tree node 时回退扫描 sample artifact 内嵌引用。
- 只返回 `/runtime/...` URI 或 `null`。

当前不承诺：

- 全局孤儿 artifact 反查。
- FunctionSlotLibrary 文件的深层 artifact 解析。
- 索引重建。

输出：

```ts
type ArtifactResolution = {
  schemaVersion: "artifact_resolution.v1";
  artifactId: string;
  artifactType: string | null;
  stageName: string | null;
  parentArtifactId: string | null;
  sampleVideoId: string | null;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  uri: string | null;
  mediaKind: "video" | "audio" | "image" | "json" | "text" | "unknown";
  exists: boolean;
  readable: boolean;
  summary: Record<string, unknown> | null;
  source: {
    sourceOfTruth: string | null;
    indexSource: string | null;
  };
};
```

### LineageResolver

文件：`Apps/Api/lib/platform/lineage-resolver.js`

职责：

- 返回资源或 artifact 的血缘图。
- 输出节点和边，不规定 UI 是树、图谱、时间线还是列表。

当前覆盖：

```text
sample
artifact
```

当前基于 `ArtifactIndex` artifact tree 构建血缘，这是可重建索引投影，不是新的事实源。

暂不推断 workflow、conversation 或 FunctionSlotLibrary 跨库深层血缘。

### RuntimeStateResolver

文件：`Apps/Api/lib/platform/runtime-state-resolver.js`

职责：

- 统一 workflow run、job、active turn 的运行状态。
- 保留 `rawStatus`，同时输出对外统一的 `status`。

当前覆盖：

```text
workflowRun
job
activeTurn
```

输出：

```ts
type RuntimeState = {
  schemaVersion: "runtime_state.v1";
  resource: ResourceRef;
  status: "idle" | "queued" | "running" | "waiting" | "blocked" | "processed" | "partial_failed" | "failed" | "canceled" | string;
  rawStatus: string | null;
  progress: number | null;
  currentStages: Array<{
    key: string;
    stageName: string | null;
    status: string;
    runId: string | null;
    traceId: string | null;
    stageId: string | null;
    artifactId: string | null;
    parentArtifactId: string | null;
    errorSummary: Record<string, unknown> | null;
  }>;
  retryable: boolean | null;
  errorSummary: Record<string, unknown> | null;
};
```

### ActionRegistry

文件：`Apps/Api/lib/platform/action-registry.js`

职责：

- 基于资源状态声明当前可用动作。
- 说明动作为什么不可用。
- 声明动作风险、确认要求、输入 schema 和影响范围。

当前 action：

| actionKey | 目标资源 | 当前状态 |
| --- | --- | --- |
| `workflow.stage.rerun` | `workflowRun` | 可声明，可通过 command 执行 |
| `job.cache.resolve` | `job` | 可声明，可通过 command 执行 |
| `agent.turn.stop` | `activeTurn` | 可声明，可通过 command 执行 |
| `agent.turn.retry` | `activeTurn` | 可声明但禁用 |
| `conversation.archive` | `conversation` | 可声明，可通过 command 执行 |

`agent.turn.retry` 当前只在旧 active-turn replay 路由中安全承接。它涉及 replay 输入校验、thread/lease 管理、新旧 turn 关系和 owner 回写；在抽出稳定 retry service 前，platform command 不执行该动作。

### CommandDispatcher

文件：`Apps/Api/lib/platform/command-dispatcher.js`

职责：

- 把 platform command 转译到已有业务 service/runtime。
- 不重新实现 workflow、cache、active turn 或 conversation 业务流程。
- 返回统一 `platform_command_result.v1`。

当前支持：

| command | 转译目标 |
| --- | --- |
| `workflow.stage.rerun` | workflow service `rerunStage` |
| `job.cache.resolve` | `moduleRegistry.resolveModuleCacheDecision` 或 `shotBoundaryService.resolveCacheDecision` |
| `agent.turn.stop` | `activeTurnRuntime.cancel` |
| `conversation.archive` | `agentConversationStore.archive` |

输出：

```ts
type PlatformCommandResult = {
  schemaVersion: "platform_command_result.v1";
  ok: boolean;
  command: string;
  target: ResourceRef;
  status: string | null;
  runId: string | null;
  traceId: string | null;
  stageId: string | null;
  artifactId: string | null;
  parentArtifactId: string | null;
  resourceRefs: ResourceRef[];
  errorSummary: Record<string, unknown> | null;
};
```

### TraceResolver

文件：`Apps/Api/lib/platform/trace-resolver.js`

职责：

- 为 platform API 输出安全 trace detail。
- 避免新 UI 直接消费旧 `/api/debug/traces/:traceId` 的完整事件结构。
- 折叠数组和复杂对象，脱敏本地路径，只返回摘要。

只接受：

```text
trace_<id>
uiTrace_<id>
```

输出：

```ts
type PlatformTraceDetail = {
  schemaVersion: "platform_trace_detail.v1";
  traceId: string;
  status: string | null;
  updatedAt: string | null;
  latestEvent: string | null;
  latestStageName: string | null;
  runId: string | null;
  stageId: string | null;
  artifactId: string | null;
  parentArtifactId: string | null;
  logUri: string | null;
  errorSummary: {
    code: string | null;
    message: string | null;
    stageName: string | null;
    retryable: boolean | null;
    debugSnapshotUri: string | null;
  } | null;
  eventCount: number;
  stages: Array<Record<string, unknown>>;
  source: {
    sourceOfTruth: "Runtime/DebugSnapshots/<traceId>.log.jsonl";
    indexSource: "Apps/Api/lib/observability/debug-traces.js";
  };
};
```

## HTTP API

实现文件：

```text
Apps/Api/lib/http/platform-routes.js
Apps/Api/lib/http/platform-errors.js
```

稳定入口：

```text
GET  /api/platform/v1/catalog
GET  /api/platform/v1/catalog?includeInternal=true
GET  /api/platform/v1/resources?kind=<resourceKind>
GET  /api/platform/v1/resources/:resourceKind/:resourceId
GET  /api/platform/v1/resources/:resourceKind/:resourceId/lineage
GET  /api/platform/v1/resources/:resourceKind/:resourceId/actions
GET  /api/platform/v1/artifacts/:artifactId
GET  /api/platform/v1/artifacts/:artifactId?sampleVideoId=<sampleVideoId>
GET  /api/platform/v1/runtime-state/:resourceKind/:resourceId
GET  /api/platform/v1/traces/:traceId
POST /api/platform/v1/commands
```

这些入口是能力接口，不是页面接口。前端可以组合它们做任何 UI 形态。

## 错误合同

platform API 错误统一返回：

```ts
type PlatformError = {
  schemaVersion: "platform_error.v1";
  error: string;
  code: string;
  message: string;
  resource: ResourceRef | null;
  traceId: string | null;
  debugSnapshotUri: string | null;
  stageName: string | null;
  retryable: boolean;
  details: Record<string, unknown> | null;
};
```

规则：

- 读接口的普通 404 不生成新的 DebugSnapshot，`traceId` 和 `debugSnapshotUri` 可为 `null`。
- command 或其他执行异常必须走 API 失败追踪，返回 `traceId` 和 `debugSnapshotUri`。
- 错误消息必须是安全摘要，不返回完整 stack、完整 prompt、完整素材内容或本地绝对路径。

API 失败追踪由：

```text
Apps/Api/lib/observability/api-request-debug.js
Infrastructure/Observability/stage-logger.js
```

负责写入 `stage.start`、`stage.fail` 和受控 DebugSnapshot。

## 和旧接口的关系

旧接口继续保留，旧 Workbench 仍可使用原有 API。

platform API 不替换旧 service，不绕过旧 workflow/job/active-turn/conversation 逻辑，而是在其上做安全投影和命令转译。

允许复用：

- `artifactIndex`
- `workflowRunStore`
- `jobStore`
- `moduleRegistry`
- `shotBoundaryService`
- `activeTurnRuntime`
- `agentConversationStore`
- `stage-logger`
- `debug-traces`

不允许：

- 为新 UI 复制一套业务流程。
- 在 platform 层重新实现模型调用、媒体处理或分析逻辑。
- 让 platform 层静默覆盖旧 artifact 或 workflow run。
- 让前端直接读 Runtime 文件或本地路径。

## 新 UI 接入建议

新 UI SDK 建议只封装平台能力，不封装页面结构：

```text
Apps/NewWorkbench/src/api/
  platformClient.ts
  resources.ts
  artifacts.ts
  runs.ts
  traces.ts
  commands.ts
```

推荐基本读取顺序：

1. `GET /api/platform/v1/catalog` 获取资源目录和能力。
2. `GET /api/platform/v1/resources?kind=<kind>` 获取列表。
3. `GET /api/platform/v1/resources/:kind/:id` 获取摘要详情。
4. `GET /api/platform/v1/resources/:kind/:id/actions` 获取当前可用动作。
5. `POST /api/platform/v1/commands` 执行动作。
6. 用返回的 `runId / traceId / artifactId` 查询 runtime state、trace 或 artifact。

## 当前稳定边界

已稳定：

- resource catalog
- resource list/read 摘要
- artifact resolution 的 sample/index 范围
- sample/artifact lineage
- workflowRun/job/activeTurn runtime state
- action declaration
- command dispatch for rerun/cache/stop/archive
- safe trace detail
- platform error schema

仍不承诺：

- 全局 artifact 反查不依赖 sampleVideoId。
- FunctionSlotLibrary 深层 artifact resolver。
- workflow、conversation、libraryItem 跨源深层 lineage。
- platform command 执行 `agent.turn.retry`。
- 分页、筛选、排序协议。
- 资源事件流或统一 polling 协议。
- 页面级 projection。
