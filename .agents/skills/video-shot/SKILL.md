# 视频镜头边界分析

## 概述

通过将自动化场景变化候选点与视觉审查相结合，估算视频包含的独立镜头数量。将自动检测器视为初筛；最终计数应以画面视角、构图或主体关系是否实际发生重置为准。

## 工作流程

1. 确认源视频。
   - 从用户请求中解析出准确的文件路径。
   - 读取基本元数据：时长、分辨率、帧率、流数量和文件大小。
   - 在报告分析结果时简要说明上述信息。

2. 执行自动化剪辑候选点扫描。
   - 使用场景变化检测器或等效的帧差分方法查找可能的硬切点。
   - 尽量测试至少两个阈值：一个较敏感0.2阈值的扫描以避免漏检，一个较严格0.35阈值的扫描以筛出稳定的高置信度剪辑点。
   - 记录候选时间戳，而非仅依赖候选数量。

3. 制作视觉审查素材。
   - 在候选剪辑点时间戳处提取代表性帧。
   - 当前后差异不明确时，优先提取每个候选点前后的帧对。
   - 同时制作粗略的时间轴采样（例如每秒一帧），以发现遗漏的结构。

4. 手动分类候选点。
   - 当视觉语法发生重置时，将候选点计为镜头边界：新构图、新摄像角度、新产品/手部摆位、新背景关系，或明显跳转至不同的演示节拍。
   - 当前后帧为同一连续动作，且仅有手部动作、产品运动、焦点变化、曝光闪烁、字幕变化或快速物体近距离经过镜头时，不计为镜头边界。
   - 对于快速蒙太奇段落，应结合相邻候选点一并审查，避免将真实的快速剪辑合并为一个镜头。

5. 计算最终镜头数。
   - 最终镜头数 = 已接受的边界数 + 1（假设视频从一个镜头开始）。
   - 若开头或结尾为黑场、片头字幕或转场段落，说明是否将其计为独立镜头。
   - 保留被拒绝的候选时间戳列表，以便解释自动化结果与最终计数之间的差异。

6. 清晰地输出报告。
   - 首先给出最终数字。
   - 提供已接受的剪辑点时间戳。
   - 说明任何边界情况的候选点及其被纳入或排除的原因。
   - 仅在对用户有参考价值时，才提及所生成的审查素材。

## 判断标准

以"镜头"（shot / 镜头）作为计数单位，而非叙事意义上的"场景"（scene）。一个镜头是一段连续的视觉取景或构建的片段。在短视频产品类视频中，硬切可能发生在相同背景和布景内；只要剪辑跳转至新的演示节拍或明显不同的构图，仍应计为一个镜头。

不确定时，优先采用保守计数并说明不确定性。用户应理解最终计数与原始检测器输出之间差异的原因。
## 工具约束
- 不支持 ffmpeg 的 glob 拼接。
- 不支持 ImageMagick。
## 输出格式

对于中文请求，以中文回答。通常简洁的回复即可：

- 视频时长及基本格式。
- 最终镜头数。
- 已接受的剪辑点时间戳。
- 边界/被拒绝的时间戳（如有）。
- 所生成的审查图像或联系表的路径（如已创建）。

避免过度声称精确度。若视频包含溶解、甩镜、大量运动模糊或风格化转场，应说明计数为估算值并指出模糊之处。
