# Video Production Prompts

## 触发条件

只有用户在 ShotDesign 阶段明确要求“视频生产模型提示词”“生视频 prompt”“给视频模型的提示词”“可投喂生产模型的提示词”或等价表达时，才使用本 reference。

视频生产模型提示词基于已经完成的 Shot 表生成。它只出现在最终聊天回复中，不写入 `shot-design.final.md`，不新增独立 artifact，不反向修改上游 `restructure.final.md`，也不重新选择槽位链、素材路径或 shot 顺序。

## 回复位置

完成 `shot-design.final.md` 后，最终聊天回复仍先按 `references/output-contract.md` 给出文件路径、摘要、台词质检状态和必要询问。若用户本轮明确要求视频生产模型提示词，在这些信息之后直接追加：

```markdown
视频生产模型提示词：

### new_shot_01
...
```

不要输出 JSON，不要要求用户另开文件查看，不要把提示词写入 Markdown 交付文件。

## 总体原则

- 每个 prompt 只服务一个普通 shot 或 shot group；封面仍以 `shot-design.final.md` 中的 `## 封面生图提示词` 为准，聊天回复里无需重复封面 prompt，除非用户明确要求。
- 提示词必须继承 Shot 表中的 `分镜画面`、`动作与运镜`、`包装说明`、`预计时长`、`必须同步点` 和 `证明功能`，不得新增上游没有的功能承诺、功效主张、价格承诺、对比结论或证据。
- 视频模型负责底层画面和动作连续性；字幕、标题条、标签、箭头、圈选、图卡、画中画等优先作为后期包装说明，不强迫视频模型生成文字。
- 如果必须让模型生成可见文字，只能使用 Shot 表或封面区块中已经确认的屏幕文字，并在避免项里写清不要乱码、不要水印、不要额外文字。
- 提示词要普通可拍、可执行，避免复杂长镜头、夸张转场、多机位调度、高成本特效、粒子爆开、三维旋转或与证明无关的炫技描述。
- 不要把 slotSubtype、atom id、binding、proof obligation、adapter 等内部结构词写进可投喂模型的提示词。

## 分策略写法

### existing_material

`existing_material` shot 不写成重新生成画面的 prompt。它已经由原素材承载，只输出剪辑使用说明：

```markdown
### new_shot_01
素材策略：existing_material，使用 `<shotRef/groupId>`
生产方式：使用原素材，不重新生成画面。
剪辑使用说明：保留原素材主体动作、构图和节奏；按 Shot 表预计时长裁切到 `<预计时长>`；不新增包装或台词，沿用原素材已有包装/字幕。
后期包装：无新增包装，沿用原素材。
避免：不要把该镜头改写为 AI 生成画面，不要新增素材中不存在的人物、场景、动作、产品状态或口播。
```

如果原素材无口播/字幕且未获授权补写，继续写“无”，不得在最终回复的提示词里偷偷补字幕或旁白。

### existing_material_packaging_caption

`existing_material_packaging_caption` shot 的底层画面仍使用原素材，不写新画面生成 prompt，只写素材剪辑和后期包装提示：

```markdown
### new_shot_02
素材策略：existing_material_packaging_caption，使用 `<shotRef/groupId>`
生产方式：使用原素材画面，在后期叠加包装/字幕。
剪辑使用说明：保留原素材代表动作和结果状态；按 Shot 表预计时长裁切到 `<预计时长>`。
后期包装：`<从 Shot 表包装说明提取可见覆盖层、位置、样式、出现时机和避让区域>`。
字幕/旁白：`<仅在 Shot 表已写明且符合授权边界时填写；否则写“无”>`。
避免：不要重新生成画面，不要伪造原素材没有的证据，不要让后期文字遮挡主体细节或关键动作。
```

如果新增字幕、屏幕文字、旁白或标签，最终聊天回复仍按 `output-contract.md` 声明“本轮包含新增台词/字幕，等待平台侧外部质检”。

### self_designed_by_shot_design

`self_designed_by_shot_design` shot 可以写完整视频生成 prompt。底图、动作和镜头连续性来自 Shot 表，包装文字仍后期叠加。

```markdown
### new_shot_03
素材策略：self_designed_by_shot_design
画幅：`<9:16 / 16:9 / 未明确，需确认>`
时长：`<预计时长>`
生成提示词：
`<主体、场景、构图、景别、视角、光线、产品状态、人物/手部姿态、轻量动作、普通运镜、真实短视频质感>`。
动作与运镜：
`<从 Shot 表动作与运镜提取，写成模型可理解的连续动作>`。
后期包装：
`<从 Shot 表包装说明提取；优先后期叠加，不让模型生成文字>`。
字幕/旁白：
`<从 Shot 表台词/字幕提取；标明口播、后期字幕、屏幕文字或旁白；无则写“无”>`。
避免：
不要生成字幕、水印、额外文字、夸张广告海报感、复杂转场、产品形态变化、证据夸大、人物手部畸形或包装文字变形。
```

生成提示词只写模型应该生成的画面和动作，不写后期剪辑说明、结构解释或内部证明任务。

### reuse_transformed_fallback

`reuse_transformed_fallback` 要写清复用变形方式，不能伪装成未占用原素材，也不能写成全新主路径：

```markdown
### new_shot_04
素材策略：reuse_transformed_fallback，复用 `<shotRef/groupId>`
生产方式：基于原素材做 `<裁切 / 放大 / 冻结帧 / 局部特写 / 变速 / 错位重入>`。
剪辑使用说明：保留原素材已有主体和证据，不新增素材中没有的动作或结果；按 Shot 表预计时长处理到 `<预计时长>`。
后期包装：`<必要的包装/字幕补强>`
避免：不要当作新拍镜头，不要重复占用原素材却标成 existing_material，不要伪造新增证据。
```

## 字段取值规则

- `画幅` 必须跟随用户或上游已确认的视频画幅；未明确时写“未明确，需确认”，不要猜。
- `时长` 必须使用 Shot 表的 `预计时长`，不得为了 prompt 擅自延长或压缩。
- `生成提示词` 必须从 `分镜画面` 和 `动作与运镜` 合成，不得加入 Shot 表没有的人物、场景、产品状态、结果状态或证明证据。
- `后期包装` 必须从 `包装说明` 提取，并保留覆盖层位置、样式、出现时机和避让区域。
- `字幕/旁白` 必须从 `台词/字幕（若有）` 提取；无台词 shot 写“无”。不得在最终回复里新增未经过 Shot 表确认的文案。
- `避免` 至少覆盖文字失控、水印、产品变形、证据夸大、素材中不存在内容、主体遮挡和过度广告化。

## 质量检查

生成最终回复里的提示词前检查：

- 是否只有用户明确要求时才输出提示词。
- 是否没有改变 `shot-design.final.md`、封面生图提示词或上游结构方案。
- 是否没有把提示词写入 `shot-design.final.md` 或新增 artifact。
- 是否没有把 `existing_material` / `existing_material_packaging_caption` 写成重新生成画面的 prompt。
- 是否每个普通 shot 或 shot group 都有对应提示词或剪辑使用说明。
- 是否所有提示词都继承 Shot 表字段，没有新增事实、证据、主张、人物、场景或产品状态。
- 是否把字幕、标签、标题条等文字优先放在后期包装，而不是强迫视频模型生成。
- 是否没有输出 JSON，也没有把内部结构词写进可投喂模型的提示词。
- 若新增或承接了非原素材逐字来源的文字，最终聊天回复是否按 `output-contract.md` 声明台词质检状态。
